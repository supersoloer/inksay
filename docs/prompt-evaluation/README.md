# 口述整理提示词评测

2026-09-29。最终采用 `src-tauri/prompts/dictation.txt` 的规则版，由 `language.rs` 追加各整理风格的要求。本次未改翻译、询问的系统提示词，也未新增界面文案。

## 变化

- 同一事项明确改口时采用最终版本；多个事项和未确认候选不能混为一次更正。
- 明确针对本次口述稿的编辑旁注直接应用，业务指令、转述和问题保留为正文。
- 保护否定、条件、理由、姓名、数字和承诺；不猜测补全事实。
- 明确枚举逐项换行，邮件不补客套和落款；上下文与词表只作为参考。
- 保留“不处理”及现有输出长度检查。

## 方法与结果

使用 Inksay 已配置的 `deepseek-chat`，temperature 0，书面语风格。全部输入均为自写合成句，没有使用用户历史录音或正文。两轮各 10 例 × 3 个变体，共 60 次请求。

原始输出和接口返回用量保存在本目录 JSON，未包含密钥。字符串断言仅用于筛查，结果另经语义检查；这不是总体准确率或其他模型、风格的质量保证。

第一轮规则版 9/10；示例版 8/10，出现列表合并。旧版自动断言 8/10，但人工检查发现两处漏报：修改指令原样残留，以及擅自增加“下午”、复述保留要求。第二轮完善断言后，旧版 5/10，规则版和示例版均 9/10。不同轮次旧版输出存在变化，不能把跨轮差异直接解释为提示词效果。

典型输出：

| 输入 | 旧版 | 规则版 |
| --- | --- | --- |
| 我们明天下午两点见，改成三点。 | 明天下午的会面时间由两点改为三点。 | 我们明天下午三点见。 |
| 方案已经通过。把已经通过改成尚未通过。 | 方案已通过，请改为尚未通过。 | 方案尚未通过。 |
| 是张宁还是章宁，我还不确定。 | 我还不确定是张宁还是章宁。 | 是张宁还是章宁，我还不确定。 |

## 消融结论

不采用额外三个示例：第一轮反而损害列表格式，第二轮无额外收益。第一轮规则版平均输入约 554 tokens，示例版约 639 tokens，旧版约 310 tokens（接口报告，包含测试句）。

第二轮增加“成稿格式、语气、保留范围也是旁注”的解释没有改善剩余用例，最终删除该增量，使用第一轮规则版。

已知限制：`周三两点给客户演示，周四三点开内部会，这两个时间都保留。` 的末句仍被保留。它有正文/编辑旁注歧义；本版没有为通过单例而加入机械删除。不能声称所有旁注都会被正确处理。

## 复现

`prompt-eval` Cargo feature 仅用于开发评测，普通正式构建不包含评测入口。通过生产配置构建并按现有脚本签名，然后以 `--prompt-eval` 启动应用。评测通过应用原有设置读取路径使用凭据，报告写到应用缓存目录的 `prompt-evaluation.json`，完成后退出。会调用当前配置的模型服务并产生用量。

`src-tauri/prompts/regression-cases.json` 是用例；`baseline-dictation.txt` 和 `dictation-examples.txt` 仅供评测，正式提示词不使用它们。默认构建不会主动运行评测。

验证：5 项语言模块测试通过；正式构建及签名校验通过，已核对打包二进制包含选定规则且不包含评测入口，并重新启动应用。未在真实录音及所有整理风格上重跑端到端评测。
